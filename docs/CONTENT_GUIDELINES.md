# 콘텐츠 작성·검증 운영 기준

이 문서는 연마의 도구 설명, 가이드와 아티클을 작성·수정할 때 사용하는 내부 기준이다. 공개 소개 페이지에는 방문자가 판단에 필요한 운영 주체, 제공 범위, 이용 한계와 문의 방법만 표시하고 상세 작업 절차는 공개하지 않는다.

## 공개 정보의 범위

- 공개 글의 작성 주체는 `HPMPLab`으로 통일한다.
- 가이드에는 최종 검증일, 확인한 기능 범위와 전문 검수 여부를 표시한다.
- 아티클에는 카테고리, 발행일과 사실·의견의 성격을 구분해 표시한다.
- 본문 분량을 바탕으로 추정한 읽기 시간(`약 N분`)은 독자에게 표시하지 않는다.
- 외부 자료를 사용하면 해당 주장 가까이 또는 글 하단에 원문 링크를 둔다.
- 건강·운동·측정·확률 정보에는 적용 한계와 중단 조건을 함께 안내한다.
- 오류 제보와 정정 요청은 공개 문의 페이지로 연결한다.

## 작성과 검증 절차

1. **구현 대조:** 시간, 단위, 계산식, 저장 범위와 지원 조건을 실제 HTML·JavaScript 구현과 대조한다.
2. **근거 구분:** 외부 연구나 공식 문서에서 확인한 사실, 앱이 선택한 기본값, 기기 제약에서 추론한 값을 구분한다.
3. **실패 조건 확인:** 정상 흐름뿐 아니라 권한 거부, 샘플 부족, 파일 형식 오류와 연결 중단 조건을 확인한다.
4. **화면 확인:** 데스크톱과 모바일에서 주요 콘텐츠, 키보드 포커스, 오류 상태, 내부 링크와 가로 넘침을 점검한다.
5. **문서 동기화:** 공개 기능이 바뀌면 관련 가이드와 `docs/현재작업중.md`를 함께 갱신한다. 검증일은 실제 재검증이 있었을 때만 바꾼다.
6. **실배포 확인:** 배포 작업 성공 여부와 `hpmplab.com`이 최신 HTML·자산을 제공하는지 별도로 확인한다.

## 독자를 위한 문장과 서사

- 첫 문단은 추상적인 평가보다 독자가 겪을 만한 장면, 질문 또는 바로 이해되는 결론으로 시작한다.
- 한 문단에서는 한 가지 질문만 답한다. 첫 문장은 문제를 열고 마지막 문장은 다음 문단이 필요한 이유를 잇는다.
- 같은 개념은 글 전체에서 같은 이름으로 부른다. 새로운 분류를 추가해야 한다면 기존 분류와의 관계부터 설명한다.
- 글 전체를 관통하는 사례 하나를 정하고, 목표·행동·기록처럼 개념이 확장될 때도 같은 사례를 이어서 사용한다.
- 연구는 독자가 알아야 할 결론을 먼저 말한 뒤, 무엇을 비교했는지와 판단에 필요한 수치만 설명한다. 연구 방법과 숫자가 문단의 첫 박자를 차지하지 않게 한다.
- 차트의 라벨 위치, 이미지 생성 방식, 후보 점수와 작업 순서 같은 제작 메모를 독자용 본문에 쓰지 않는다. 차트가 보여주는 시장 의미만 설명한다.
- 목록과 표는 항목을 비교하거나 실제로 실행할 때만 사용한다. 목록을 연속해서 배치하지 않고, 목록 뒤에는 독자가 무엇을 선택할지 설명한다.
- `HC-###`, 작성 큐, 내부 자료팩 같은 편집 정보는 공개 본문에 노출하지 않는다. 글의 끝에는 이번 글의 결론, 지금 해볼 행동과 실제로 공개된 다음 읽을거리 하나만 둔다.
- 초안은 소리 내어 읽어 주어·행동·결론이 한 번에 잡히는지 확인한다. 뜻을 이해하려고 앞 문장을 다시 읽어야 하면 추상명사를 동사와 구체적인 장면으로 바꾼다.

## 자동화 도구 사용

- 코드·문서 초안, 반복 검사와 형식 정리에 자동화 도구를 사용할 수 있다.
- 자동화 결과를 사실로 바로 게시하지 않고 실제 코드, 브라우저 동작과 인용 원문을 대조한다.
- 직접 측정하지 않은 효과나 사용 경험을 측정한 것처럼 서술하지 않는다.
- 자동 생성 여부보다 게시된 내용의 정확성, 고유한 편집 가치와 검증 가능한 근거를 우선한다.

## 시황 대표 이미지

- 시황 썸네일은 이전 이미지의 분위기나 소재를 생성 기준으로 삼지 않는다. 당일 리서치에서 중요도가 가장 높은 사건 1~2개로 새 시각 논제를 만든다.
- 생성 전에 `주도 사건`, `시장 방향`, `독자에게 남길 감정`, `색과 빛`을 정한다. 제목·도입부·대표 이미지가 같은 사건을 말해야 한다.
- 약세장도 검정·차콜 배경과 붉은 하락 화살표를 관성적으로 반복하지 않는다. 공급 부족, 포지션 이동, 정책 변화, 반등 조건 등 그날만의 구조를 밝은 자연광과 선명한 대비로 표현할 수 있다.
- 밝은 아이보리·하늘색·청록·금색·산호색 등 색 범위를 넓히고, 실제 긴급 충격이 핵심일 때만 어두운 톤을 제한적으로 사용한다.
- 글자, 숫자, 로고와 워터마크는 넣지 않는다. 1200×630 가로형으로 만들고 모바일 중앙 크롭에서도 핵심 피사체가 남아야 한다.
- 이전 대표 이미지는 생성 참조로 넣지 않는다. 게시 전 목록 화면에서 소재·구도·주조색이 최근 글과 겹치는지만 확인한다.
- 이미지 설명은 독자가 시황의 핵심 사건을 이해하도록 작성하며 생성 방식, 배치 지시, 라벨 처리 같은 내부 편집 메모를 쓰지 않는다.

## 안전과 표현

- `A가 아니라 B다` 식의 대조형 부정 문장을 문단마다 되풀이하지 않는다. 사실은 먼저 직접 문장으로 쓰고, 해석의 범위와 이용 한계는 글 상단 고지와 해당 주장 가까이에 한 번만 둔다.
- 연마는 의료기관, 전문 코칭 기관, 복권 판매·예측 서비스가 아니다.
- 전문 자격자의 검토를 받지 않은 글은 이를 암시하지 않는다.
- 의료 진단·치료 효과, 수익, 당첨이나 측정 정확도를 보장하지 않는다.
- 논문 조건과 앱 구현이 다르면 동일한 프로토콜이라고 표현하지 않는다.
- 호흡·숨참기·손가락 로딩처럼 안전과 관련된 글에는 통증, 어지러움과 비정상적인 불편이 있을 때의 중단 안내를 둔다.
- 로또 관련 글은 모든 유효 조합의 당첨 확률이 같으며 과거 빈도나 앱 점수가 다음 회차를 예측하지 못한다는 점을 명시한다.

## 정정

재현 가능한 오류는 원인이 확인된 뒤 코드와 관련 문서를 함께 수정한다. 화면, 브라우저, 입력값과 재현 순서가 있으면 우선 확인하며, 개인의 부상 진단·의료 판단·제품 구매 보증과 당첨 번호 상담은 답변 범위에 포함하지 않는다.
