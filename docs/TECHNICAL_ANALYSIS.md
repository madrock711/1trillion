# 고급 차트 분석

시황 페이지의 **기술적 분석 → 고급 차트 분석**에서 KODEX 레버리지, KOSPI, TQQQ의 가격과 거래량을 분석한다. 매물대, 앵커 VWAP, 추세 지표, 여러 시간 단위의 비교, 과거 재생, 그리기, 차트 설정 저장, 복합 조건 알림과 CSV 내보내기를 제공한다.

TradingView의 공개 기능 설명과 널리 알려진 지표 정의를 참고해 OHLCV 계산과 화면을 독립적으로 구현했다. 비공개 소스, 유료 계정 내부 코드나 전용 데이터 피드는 분석하지 않았다. 아래 공식 문서는 기능과 수식의 참고 자료이며, TradingView와 계산 결과·UI·유료 기능 전체가 동일하다는 뜻은 아니다.

## 사용 방법

1. 시황 페이지에서 **기술적 분석**을 열고 **고급 차트 분석**의 종목과 원본 봉을 선택한다. 분봉 거래일과 원본 간격은 아래 공통 차트 설정에서 바꾼다.
2. **시간 단위**에서 일봉·주봉·월봉 또는 지원되는 분봉 간격을 고른다. **표시 봉 수**는 60·120·240·전체 중 선택한다.
3. 필요한 지표를 켠다. 보조 지표는 RSI와 MACD 중 하나를 표시하거나 숨길 수 있다. 캔들·하이킨 아시·종가선과 일반·로그 가격 축도 선택한다.
4. VWAP 계산을 시작할 봉은 **VWAP 시작** 목록에서 고르거나, **그리기 → VWAP 시작점**을 선택한 뒤 차트에서 지정한다.
5. **수평선**은 한 지점, **추세선**과 **피보나치 되돌림**은 두 지점을 선택한다. **그리기 취소**는 선택 중인 첫 지점 또는 마지막 그리기를 취소하고, **선 모두 지우기**는 현재 종목·원본 봉·시간 단위의 그리기를 지운다.
6. **과거 재생**을 누른 뒤 위치 슬라이더, **다음 봉**, **재생**으로 시점을 이동한다. **최신으로**를 누르면 전체 데이터로 돌아온다.
7. **차트 설정 저장**에 이름을 입력해 현재 구성을 저장한다. **복합 조건 알림**에서는 지표·비교 방식·기준값을 입력하고 AND 또는 OR로 결합해 저장한다.
8. **CSV 내보내기**로 선택한 시간 단위의 가격·거래량·계산 가능한 지표를 내려받는다. 과거 재생 중에는 재생 시점까지의 값만 담는다.

차트에 초점을 둔 상태에서 좌우 방향키로 봉을 이동하고, Home·End로 첫 봉·마지막 봉을 선택할 수 있다. Enter는 선택한 봉의 종가를 그리기 지점으로 사용하며, Escape는 선택 중인 지점을 취소한다.

일봉은 연결된 전체 이력으로 지표를 계산한 뒤 표시 봉 수만큼 잘라 보여 준다. 따라서 화면을 120봉에서 60봉으로 줄여도 EMA·RSI의 계산 시작점은 바뀌지 않는다. 매물대는 화면에 표시한 봉을 대상으로 하므로 표시 봉 수를 바꾸면 결과도 바뀐다.

### OHLCV와 시간 단위

OHLCV는 시가·고가·저가·종가·거래량이다. 유효한 날짜·시각, 양수 가격, 고가·저가 관계를 검사하고 잘못된 봉은 제외한다. 같은 날짜·시각이 중복되면 마지막 유효 정정값을 사용한다. 거래량 결측은 `null`로 보존하고 실제 거래량 0과 구분한다.

주봉은 월요일을 시작일로, 월봉은 해당 월의 1일을 기준으로 묶는다. 각 묶음의 첫 시가, 최고가, 최저가, 마지막 종가와 거래량 합계를 사용한다. 하나라도 거래량이 없으면 묶음의 거래량도 결측으로 남긴다.

분봉은 원본보다 크고 원본 간격으로 나누어떨어지는 5·15·30·60분 간격만 제시한다. 예를 들어 15분 원본에서는 30분과 60분으로 묶을 수 있다. 원본보다 짧은 봉을 만들어 내지는 않는다. 거래소 현지 날짜·봉 시각을 사용하며, 같은 거래일의 00시를 기준으로 선택한 간격에 맞춰 묶는다. 거래소 개장 시각에 맞춰 봉을 정렬하는 서비스와 경계가 다를 수 있다.

### 매물대와 가치 영역

표시 범위의 가격을 32개 구간으로 나누고, 각 봉의 거래량을 고가·저가와 겹치는 가격 구간의 길이에 비례해 분배한다. 고가와 저가가 같으면 그 가격 구간에 전량을 넣는다. 가장 많은 추정 거래량이 담긴 구간의 중앙을 POC로 표시한다.

가치 영역은 POC에서 시작해 양옆 중 거래량이 큰 구간을 차례로 포함하고 총 추정 거래량의 **70% 이상**이 될 때까지 확장한다. 경계가 VAH와 VAL이다. 거래량이 같으면 아래 구간을 먼저 선택한다. 구간 단위로 포함하므로 70%를 초과할 수 있다. [TradingView의 매물대 기본 개념](https://www.tradingview.com/support/solutions/43000502040-volume-profile-indicators-basic-concepts/)은 하위 시간봉으로 계산하는 방법과 POC·가치 영역을 설명한다. 이 구현은 연결된 OHLCV의 균등배분 추정이며, 세부 배분과 가치 영역의 종료·동률 처리 방식도 다르다.

거래량이 있는 봉만 계산에 포함한다. 일부 봉의 거래량이 빠지면 해당 봉의 가격 범위와 거래량은 매물대에 반영되지 않는다. 전부 결측이거나 합계가 0이면 매물대와 POC·VAH·VAL을 표시하지 않는다. 호가별 잔량, 실제 가격별 체결량, 매수·매도 주도 체결량을 나타내는 지표로 해석해서는 안 된다.

### 앵커 VWAP와 밴드

대표 가격은 `HLC3 = (고가 + 저가 + 종가) / 3`이다. 선택한 시작 봉부터 `Σ(HLC3 × 거래량) / Σ거래량`을 계산한다. 밴드는 같은 구간의 HLC3에 대한 거래량 가중 모집단 표준편차를 사용하며, VWAP 위아래에 ±1σ로 표시한다. 큰 가격에서도 분산 계산의 오차를 줄이기 위해 가중 Welford 갱신을 사용한다.

시작점 이후 거래량 결측이 나오면 그 봉부터 VWAP와 밴드를 표시하지 않는다. 거래량 0은 평균에 새로운 가중치를 더하지 않으며, 누적 거래량이 0이면 값은 결측이다. 시작점이 재생 시점보다 뒤에 있거나 현재 불러온 이력에 없으면 VWAP와 밴드를 표시하지 않는다. 저장한 시작점이 이력에서 빠져도 첫 봉으로 바꾸지 않으며, 시작점 목록에 **현재 범위 밖**으로 남긴다. [TradingView의 VWAP Auto Anchored 문서](https://www.tradingview.com/support/solutions/43000652199-vwap-auto-anchored/)에 공개된 HLC3 입력과 표준편차 밴드를 참고했다. 현재 시작점은 사용자가 지정하며, 고점·실적·배당을 자동으로 찾는 기능은 없다.

### 추세와 모멘텀 지표

ATR의 실제 범위는 고가−저가, 고가와 직전 종가 차이의 절댓값, 저가와 직전 종가 차이의 절댓값 중 최댓값이다. 첫 봉은 고가−저가를 사용한다. 처음 10봉의 단순 평균으로 시작한 뒤 Wilder 평균을 적용한다. [TradingView의 ATR 문서](https://www.tradingview.com/support/solutions/43000501823-average-true-range-atr/)도 실제 범위와 기본 RMA 평활 방식을 설명한다.

슈퍼트렌드는 `(고가 + 저가) / 2 ± 3 × ATR 10`에서 밴드를 만들고, 직전 밴드와 종가를 이용해 밴드를 유지하거나 갱신한다. 종가가 밴드를 돌파하면 방향을 전환한다. 첫 ATR 값이 나오는 시점의 방향은 하락으로 시작한다. 공개 수식은 [TradingView의 Supertrend 문서](https://www.tradingview.com/support/solutions/43000634738-supertrend/)를 참고했다.

RSI 14는 처음 14번의 종가 변화에서 평균 상승폭과 하락폭을 구한 뒤 Wilder 평균으로 갱신한다. 평균 하락폭만 0이면 100, 상승폭만 0이면 0, 둘 다 0이면 50으로 처리한다. 첫 값에는 15봉이 필요하다. 기본 수식과 RMA 정의는 [TradingView의 RSI 문서](https://www.tradingview.com/support/solutions/43000502338-relative-strength-index-rsi/)를 참고했다.

EMA는 처음 N봉의 단순 평균을 시작값으로 사용하고 이후 `α = 2 / (N + 1)`로 갱신한다. EMA 20·50은 각각 20번째·50번째 봉부터 표시한다. MACD는 EMA 12−EMA 26이며 신호선은 MACD의 EMA 9다. 현재 시작값 규칙에서는 MACD는 26봉, 신호선과 히스토그램은 34봉부터 계산된다. [TradingView의 EMA 문서](https://www.tradingview.com/support/solutions/43000592270-exponential-moving-average/), [MACD 문서](https://www.tradingview.com/support/solutions/43000502344-moving-average-convergence-divergence-macd-indicator/)에 공개된 정의를 참고했다. 이력 길이와 시작값이 다른 차트 서비스에서는 같은 지표라도 값이 달라질 수 있다.

### 하이킨 아시와 과거 재생

하이킨 아시는 차트의 캔들 가격만 변환한다. 종가는 원본 시가·고가·저가·종가의 평균이며, 시가는 직전 하이킨 아시 시가·종가의 평균이다. 첫 시가는 원본 시가·종가의 평균으로 시작한다. 지표, 거래량, 알림과 CSV에는 변환 전 가격을 사용한다.

과거 재생은 불러온 원본 이력의 중간 시점에서 시작하며 슬라이더로 다른 시점을 선택할 수 있다. 매번 원본 이력을 재생 시점까지 먼저 자른 다음 시간 단위를 묶고 지표·패턴을 다시 계산한다. 미래 봉의 가격·거래량이 현재 지표에 들어가지 않는다. 주봉·월봉도 재생 시점까지 들어온 봉만으로 계산하므로 진행 중인 봉은 최종 OHLCV와 다를 수 있다. 미래 시점의 지점이 포함된 그리기도 숨긴다.

재생 속도는 원본 봉당 0.5·1·2초다. 브라우저 탭을 숨기거나 다른 시황 화면으로 이동하면 자동 재생을 멈춘다. 종목·원본 봉 모드·저장한 차트 설정을 바꾸면 재생을 끝내고 최신으로 돌아간다. 원본 분봉 간격을 바꾸거나 거래일 변경으로 재생 기준 봉이 새 이력에서 빠진 경우에도 최신으로 돌아가 현재 데이터로 알림 감시 상태를 다시 잡는다. 주문 체결, 거래 비용, 성과 계산을 제공하는 전략 백테스트는 포함하지 않는다.

### 이중 천장·바닥

각 극값은 좌우 3봉보다 엄격하게 높거나 낮아야 하며, 오른쪽 3봉이 들어온 뒤 확정한다. 연속한 같은 종류의 극값 중 간격이 6~80봉이고 가격 차이가 평균 극값의 2% 이내인 쌍을 찾는다. 두 극값 사이 반대 극값으로 목선을 정하며, 극값과 목선의 차이가 1% 이상이어야 한다.

두 번째 극값이 확정된 이후 종가가 목선을 돌파해야 패턴을 표시한다. 그 전에 종가가 패턴의 바깥 극값을 2% 넘어서면 후보를 무효화한다. 최근 120봉 안에 두 번째 극값이 있는 후보를 검사하고 화면에는 최근 5개를 표시한다. 이 규칙은 제한된 후보 탐지 방식이며, 모든 차트 패턴을 찾거나 매매 성과를 보장하지 않는다.

## 알림과 브라우저 저장

복합 조건 알림은 종가, RSI 14, MACD 히스토그램, 앵커 VWAP, 슈퍼트렌드의 **고정 숫자 기준값**을 비교한다. 초과·미만·상향 돌파·하향 돌파를 지원하며 한 알림에 최대 5개 조건을 AND 또는 OR로 결합한다. 가격과 이동평균처럼 두 지표를 서로 비교하는 조건은 지원하지 않는다.

알림은 저장할 때의 종목·원본 봉 모드·원본 간격에 연결된다. 화면에서 주봉이나 월봉을 선택했어도 알림은 원본 일봉 또는 원본 분봉으로 계산한다. VWAP는 저장할 때의 시작점을 사용하며, 묶은 시간봉에서 고른 시작점은 그 묶음에 포함된 첫 원본 봉으로 연결한다. 지표 계산에 필요한 이력이 부족하면 해당 조건은 계산 불가로 취급한다. 저장한 시작점이 원본 이력에 없거나 시작점 이후 거래량이 결측이면 VWAP 조건도 계산하지 않는다.

최초 값은 감시의 기준 상태로만 저장한다. 이후 새로운 데이터가 들어와 조건이 불충족에서 충족으로 바뀌면 화면 상태 문구와 최근 충족 시각을 갱신한다. 이미 충족 상태인 조건을 반복 통지하거나 지난 충족을 소급 통지하지 않는다. 알림 저장 시점이나 마지막 감시 봉보다 오래된 이력은 평가하지 않으므로, 이전 거래일을 열어도 과거 조건 충족을 새 알림으로 기록하지 않는다. 현재 봉이 갱신될 때도 조건을 평가하므로 봉 마감만을 기다리는 알림은 아니다. 과거 재생 중에는 알림을 멈추고, 최신으로 돌아오면 현재 값으로 감시 상태를 다시 잡는다.

알림 감시는 이 페이지의 데이터 갱신에 의존한다. 페이지를 닫은 뒤 실행하는 서버 감시, 브라우저 푸시, 이메일·문자·소리 통지는 없다. 원본 간격을 바꾸면 저장한 간격의 데이터가 다시 들어오기 전까지 해당 알림은 평가되지 않는다.

차트 설정은 최대 20개, 알림은 최대 40개, 그리기는 종목·원본 봉·시간 단위별 최대 100개를 이 브라우저의 `localStorage`에 저장한다. 설정 이름이 같으면 덮어쓴다. 이름으로 저장하는 설정에는 종목, 원본 봉, 시간 단위, 차트 종류, 가격 축, 표시 봉 수와 지표 구성이 들어간다. 그리기와 VWAP 시작점은 별도로 보존한다. 다른 기기와 동기화하지 않으며, 브라우저 저장 데이터를 지우면 함께 사라진다. 저장 공간을 사용할 수 없으면 현재 화면에서만 유지한다.

## CSV와 데이터 범위

CSV는 화면에 보이는 마지막 60·120·240봉에 한정하지 않고, **선택한 시간 단위로 계산한 전체 이력**을 내보낸다. 과거 재생 중에는 재생 시점까지의 이력이다. 날짜·시각·OHLCV와 계산 가능한 지표 열을 포함하고 결측 셀은 비워 둔다. 매물대, 패턴, 그리기와 저장한 알림은 CSV에 들어가지 않는다. UTF-8 BOM을 넣어 한글 스프레드시트 프로그램에서 열기 쉽게 하며, 날짜·시각 등 문자 셀의 수식 실행을 막는다.

고급 차트 분석이 새 시세 피드를 직접 요청하지는 않는다. 기존 KOSPI·KODEX·TQQQ 차트가 불러온 데이터가 갱신되면 같은 데이터를 받아 다시 계산한다. 일봉은 해당 차트에 연결된 전체 이력을 받으며, 분봉은 선택 거래일까지 표시하도록 연결된 거래일 구간을 받는다. 현재 기본 분봉 표시 범위는 최대 4거래일이다. 아래 차트의 지표 예열용 14거래일이 모두 고급 차트로 전달되는 것은 아니다.

**전체**는 현재 불러온 전체 데이터를 뜻한다. 더 오래된 일봉, 수개월의 분봉이나 초 단위 이력을 추가로 불러오는 기능은 없다. 주봉·월봉에서는 봉 수가 크게 줄어 장기 지표를 계산하지 못할 수 있다. 표시된 마지막 원본 봉의 날짜·시각과 결측값을 함께 확인해야 한다. 체결 틱, 호가, 주문 흐름, 거래소의 가격별 실제 체결량은 연결하지 않는다.

## KODEX 거래량 X-ray의 RSI·MFI

KODEX 레버리지 일봉과 분봉의 거래량 X-ray에 RSI 14(보라 점선)와 MFI 14(초록 실선)를 겹쳐 표시한다. 두 지표는 오른쪽의 고정 0~100 축을 공유하며 거래량·CVD의 크기와는 별도로 읽는다. RSI의 참고 구간은 30/70, MFI는 20/80이다. 봉을 선택하면 읽기 영역에 두 지표의 값이 나온다.

[참고 영상](https://www.youtube.com/watch?v=qPH7xFr72B0)의 0:20~0:52 계산 설명과 2:25~2:56 비교, 3:17~3:45 구간을 확인했다. MFI는 대표가격 (고가+저가+종가)/3에 거래량을 곱하고, 직전 대표가격보다 오르면 양의 흐름, 내리면 음의 흐름으로 나누어 최근 14봉의 양의 흐름 / 전체 흐름 × 100으로 계산한다. 대표가격이 같으면 양·음 양쪽에 포함하지 않는다. 공식 정의는 [TradingView MFI 문서](https://www.tradingview.com/support/solutions/43000502348-money-flow-mfi/)를 참고했다.

첫 비교를 위한 이전 봉을 포함해 15봉이 필요하다. 거래량이 결측인 14봉 구간에서는 MFI를 표시하지 않고 선도 끊는다. 양·음 흐름이 모두 0이면 50으로 처리한다. 전체 일봉 이력 또는 분봉 예열 이력에서 계산한 뒤 표시 구간을 자르므로 탐색 범위를 바꿔도 같은 봉의 값이 유지된다. 분봉 간격을 바꾸면 해당 간격의 OHLCV로 다시 계산한다. CSV에 MFI 열도 포함한다. 영상의 비트코인 매매 조건을 KODEX의 자동 매매 신호로 적용하지 않는다.

## 차트 데이터 로딩

KODEX와 TQQQ 일봉은 전체 시세·환율·수급 갱신과 별도로 불러온다. 각 종목의 응답이 도착하면 고급 차트에 바로 전달하며, 다른 시세 요청이 지연되거나 실패해도 이력은 보존한다. 이력 요청에는 30초 제한을 두고 기존 차트 새로고침으로 재시도한다. 개장 전에도 확정된 일봉 이력을 받아 표시한다. 저장된 분봉 설정은 대시보드의 공통 제어기가 준비된 뒤 다시 적용한다.
