# 장전 리서치 자동화 종합 점검

## 결론과 이전 판단 정정

반복 미발행의 중심 문제는 조사 초기에 최종 응답을 보내는 실행 제어 실패다. 복구 가능한 권한·통신 오류, 배포 후 증적 변경으로 다음 실행을 막는 상태 관리, 날짜를 고정한 임시 발행 코드가 겹쳤다. 추론 수준 변경은 보조 조치다. low에서도 완료한 반례가 있어 단독 원인으로 볼 수 없다. 사용자가 말한 짧은 실패 시간을 고정 타이머 문제로 좁힌 이전 설명은 잘못이었다.

기존 종료 금지 문구와 check_market_run.py는 실행을 강제 지속시키지 않는다. 앞선 대책은 근본 해결이 아니다. 조치 적용, 개별 도구 성공, 전체 무인 발행 성공은 구분한다.

## 내부 요인

- 완료 조건을 알고도 조사 단계에서 최종 응답을 보냈다. 미완료 상태 저장은 복구나 발행이 아니다. 사용자 재지시가 사실상 재시작 장치였다.
- 매일 collect/build/seal/verify를 날짜·제목·시장상태를 고쳐 재작성했다. 자료 조사 외에 발행 코드 작성까지 반복됐다. 11/04 빌더의 이미지 전역 치환은 과거 카드까지 오염시켰다.
- 단계 상태 키가 finalQuery/finalQuote, deploy/deployment로 섞인다. 현재 검사는 증거 존재 확인이며 Git·배포·URL 검증 대체물이 아니다.
- 과거 누적 평가 해시 오류, 오늘 계약 오류, 출처 누락을 구분하지 않으면 오늘 발행을 과거 정비에 종속시키게 된다. 오늘 필수 계약 오류는 고치되 과거 오류만으로 오늘 작업을 포기하지 않는다.
- 추론 high는 유지하되 해결 증거로 삼지 않는다. low 성공 기록이 있고, 실제 예약의 재지시 없는 전체 완료로 평가해야 한다.

## 현재 적용하고 시험한 변경

- 기존 모델·평일 08시·ACTIVE를 보존하고 추론 high 설정을 확인했다. 보조 조치로 취급한다.
- scripts/collect_market_evidence.py를 공통 수집기로 추가했다. 날짜 고정 코드 복사 없이 실제 KST 날짜 아래 매 실행마다 새 디렉터리를 만든다. 한 출처 실패가 다른 수집을 중단시키지 않으며 원문 해시·조회시각·출처별 오류·manifest를 남긴다. 한 건이라도 실패하면 exit 1이다.
- 단일 출처 실패 주입 테스트로 다른 출처와 오류 기록 보존을 확인했다. 오늘 실제 20종 수집이 모두 성공했다. 수집 성공은 거래일·시각 검증이나 집필 완료가 아니다.
- 실제 금리차 도구로 감사 폴더에 최신 두 차트를 생성했다. 공개 기사·차트는 변경하지 않았다.
- check_market_run.py는 보조 점검으로 유지한다. exit 2는 남은 작업 확인이며 외부 차단이나 정당한 종료 사유가 아니다.

## 다음 실행의 고정 순서와 복구 분기

1. 실제 시작 시각·기존 상태·Git·사이트 대조 → 지침/계약/스킬 확인 → 기존 변경 보존 및 fetch/rebase. 이미 알려진 추적 증적 변경은 원문 확인 후 관련 증적 보존으로 처리하고 임의 stash/reset하지 않는다.
2. python scripts/collect_market_evidence.py 실행. 일반 환경 DNS 실패 시 같은 명령을 승인 재시도한다. 거부는 우회하지 않는다. collection-status.json을 보고 실패 출처를 보완한 뒤 거래일·시장상태·원천시각을 검증한다. 수집 성공 직후 취재 노트로 진행한다.
3. 취재 노트 → 보고서·공개 기사·대시보드·신규 이미지 → 관련 검증. 기존 빌더는 날짜·제목·링크·각 기사 og:image를 대조한다. 공통 집필·빌더 전체는 아직 구현되지 않았다.
4. 준비 완료 후 python scripts/collect_market_evidence.py --final로 국내값·환율·선물을 병렬 조회한다. 원천시각 검증 후 기사·대시보드·계약을 같은 값으로 봉인한다. 수집 경로는 명령 출력에서 찾는다.
5. 관련 테스트·diff·Bash 훅/가드 후 관련 변경만 commit/push. Python에서 Bash 호출 시 shutil.which('bash')가 반환한 절대 경로를 사용한다. PowerShell에서는 기존 안전 실행기 또는 명시적 Git Bash 사용.
6. 최종 commit의 Amplify SUCCEED·remote main·두 도메인 cache-busted 기사/자산 바이트·브라우저를 대조한다. 발행 이벤트를 추가 커밋했다면 그 최종 커밋도 확인한다. 마지막 상태 갱신으로 추적 변경을 남기지 않는다.

## 아직 해결되지 않은 구조

공통 수집기는 수집 구간만 안정화했다. 에이전트가 최종 응답을 보내면 다시 실행시키는 독립 감독기와 공통 집필/봉인/배포 실행기는 아직 없다. 지원 여부를 검증하지 않은 stop hook이나 다른 예약을 만들어 해결됐다고 보고하지 않는다.

이번 결과는 종합 진단과 일부 실행 경로 개선 완료다. 전체 무인 발행 복구는 미검증이다. 후속 개선은 단계별 실행 공통화, 중단 후 재개·중복 발행 방지·권한 거부·출처 장애를 포함한 전체 실행 시험이다. 실제 예약이 사용자 재지시 없이 최종 라이브 확인까지 완료해야 복구로 판정한다. 오늘 기사는 여전히 미발행이다.

## 발행 실행 구조 구현과 실제 시험 절차

위 내용은 08:39 감사 시점의 상태다. 이후 `scripts/publish_market_research.py`를 구현했다. 취재·집필·이미지를 검토한 뒤 일별 `package.json`에 원고/보고서템플릿/대시보드/이미지/전략/선별파일 경로를 넣고 다음 명령으로 발행한다.

```powershell
python scripts/publish_market_research.py --package research/evidence/YYYY-MM-DD/package.json
```

실행기는 최종조회→시각/시장상태 검증→기사/목록/대시보드/전망 봉인→관련 테스트/훅→선별 commit/push→그 SHA의 Amplify 대기→두 도메인 실제 바이트 비교→최초 공개시각과 발행이벤트 후속커밋→최종 SHA 재배포/라이브 확인을 처리한다. 브라우저 렌더 확인은 에이전트가 마지막에 별도로 수행한다.

체크포인트는 Git에서 제외한 `pipeline-state.json`에 원자적으로 보존한다. 명령별 exit code를 남기고 오류는 성공 상태로 바꾸지 않는다. 재실행은 콘텐츠 커밋이 있으면 원고와 전망을 다시 만들지 않고 push/배포 확인부터 이어간다. `--stop-after content_push`는 실제 재개 시험용으로 exit 75를 반환한다. 즉시 같은 package로 옵션 없이 재실행해 배포를 마친다. 이전 카드 HTML과 JSON-LD 이미지는 그대로 보존하고 오늘 카드만 삽입/교체한다.

자동으로 조사 주제와 원고를 생산하는 별도 감독기는 설치하지 않았다. 대신 준비된 package 이후의 발행 구간은 한 실행기로 묶었다. 일별 처음부터 끝까지의 무인 성공 여부와 오늘 실행기의 실제 push 후 재개 시험 결과는 로컬 증거로 구분해 확인한다. 원문/전략 입력을 검토하는 동안의 모델 조기 종료를 운영체제 수준으로 강제 차단하는 기능이라고 설명하지 않는다.
