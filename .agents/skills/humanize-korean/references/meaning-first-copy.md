# 짧은 공개 문구의 의미 우선 편집

UI 문구와 소제목은 짧아도 뜻이 자명해야 한다. 멋있어 보이는 압축보다 독자가 실제로 이해할 내용을 먼저 고른다.

## 역할별 점검

모든 문구에 같은 성분을 요구하지 않는다. 문구가 맡은 역할에 필요한 질문만 고른다.

- 메뉴·레이블: 대상을 바로 식별할 수 있는가.
- 버튼·행동 안내: 누르면 무엇을 하거나 어떤 결과가 생기는가.
- 제목·소제목: 뒤에 이어질 내용을 정확히 가리키는가.
- 카드·검색 요약: 실제 글의 관찰이나 판단을 대표하는가.
- 안전 문구: 어떤 조건에서 무엇을 해야 하는가.
- 방법론·정정문: 독자에게 보고해야 할 절차와 변경 내용을 정확히 말하는가.

필요한 정보가 원문과 문맥에 없으면 임의로 보완하지 않는다. 익숙한 말로 풀어도 뜻을 확정할 수 없으면 질문하거나 보류한다.

## 자주 실패하는 방식

- 낯선 명사 둘을 붙여 새로운 이름처럼 만든다.
- 관계가 불분명한 두 절을 `~보다`, `~에서`, `~으로`로 연결한다.
- `기록한다`, `확인한다`, `남긴다`를 붙여 구체적인 내용이 생긴 것처럼 보이게 한다.
- 카드·검색 요약에서 편집자의 검증 절차나 정보 배치 원칙을 실제 내용 대신 내세운다.
- 실제 관찰이 없는데 `명확하게 보여 준다`, `신뢰할 수 있게 구성했다`처럼 운영 메모를 홍보 문장으로 바꾼다.
- 짧게 보이려고 필요한 주체, 조건, 비교 대상을 생략한다.
- 균형 잡힌 듯 보이려고 세 명사를 쉼표로 늘어놓고 모두 같은 층위라고 가정한다.

## 선택 기준

- 정보가 빠져 뜻이 흐린 압축문은 필요한 만큼 풀어 쓴다. 표제·버튼·캡션·에세이의 의도된 단문은 완전문으로 늘리지 않는다.
- 익숙한 일반어와 낯선 조어 중에서는 일반어를 고른다.
- 카드·검색 요약에서는 제작 과정과 실제 글의 내용 중 실제 내용을 고른다.
- 제작자용 운영 원칙과 독자가 궁금한 내용 중에서는 독자가 궁금한 내용을 고른다. 방법론처럼 운영 원칙 자체가 본문이면 보존한다.
- 문장으로 만들 이유가 없으면 억지 서술어 없이 명사구를 쓴다.

## 어감이 확실하지 않을 때

1. 프로젝트가 정의한 고유 용어인지, 해당 분야의 공식 문서가 쓰는 표준 용어인지 먼저 확인한다.
2. 뜻과 문법은 국립국어원 [표준국어대사전](https://stdict.korean.go.kr/main/main.do)이나 [우리말샘](https://opendict.korean.go.kr/main)에서 확인한다. 사전 등재만으로 자연스러운 연어라고 단정하지 않는다.
3. 공개 영향이 크고 낯선 결합은 서로 다른 작성자의 같은 분야 한국어 문맥 두 개 이상에서 같은 뜻으로 쓰이는지 확인한다. 문장 일부가 아니라 앞뒤가 있는 완전한 용례를 본다.
4. 검색 결과 수만으로 자연스러움을 판정하지 않는다. 검색할 수 없거나 용례가 엇갈리면 익숙한 일반어로 풀거나 의도를 확인한다.
5. 스킬 개선 작업에서 외부 용례를 근거로 원칙을 추가할 때만 출처와 확인 날짜를 원장에 기록한다. 일반 윤문마다 조사 기록을 만들지는 않는다.

## 보류해야 하는 경우

문체 편집만으로 다음을 결정하지 않는다.

- 호흡법, 훈련법, 의료·안전 지침의 핵심 전제
- 작성자가 실제로 관찰하거나 믿는 내용
- 낯선 용어가 의도된 고유 개념인지 단순 조어인지
- 요약에서 어떤 사실을 대표로 내세울지

이 정보가 원문이나 프로젝트 문맥에 없으면 문장을 꾸며 메우지 말고 확인한다.

카드·검색 요약에 실제 내용은 없고 제작자용 운영 메모만 있다면, 그 메모를 유창하게 고치는 것은 통과가 아니다. 대화에서는 요약할 관찰이나 판단을 확인한다. 파일 편집에서는 근거 없는 대체 문구를 넣지 않는다. 방법론·정정문·투명성 보고서처럼 절차 자체가 독자에게 필요한 글에는 이 제한을 적용하지 않는다.
