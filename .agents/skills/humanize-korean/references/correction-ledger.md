# 한국어 교정 원장

사용자 교정에서 반복 가능한 원칙만 남긴다. 예문을 정답 문장으로 복사하지 말고 적용 범위와 반례를 함께 읽는다.

## 교정 유형

- **문체 교정**: 원래 뜻과 사실을 보존한다.
- **의미·사실 정정**: 사용자가 새로 밝힌 의도를 우선한다. 의료·법률·금융처럼 위험이 큰 사실은 별도로 검증한다.
- **일반 원칙 제안**: 한 문장의 정답으로 보지 않고 범위와 반례를 검토한다.

일반 윤문 중에는 이 파일을 수정하지 않는다. 사용자가 스킬 개선이나 교정 학습을 명시적으로 요청한 경우에만 후보를 기록한다.

## 상태 기준

- `후보`: 한 문맥에서 발견했거나 아직 반례 평가를 거치지 않은 원칙. 일반 윤문에 자동 적용하지 않는다.
- `활성`: 서로 다른 문맥에서 반복됐거나, 사용자가 공통 원칙으로 명시했고 긍정 사례와 반례 평가를 모두 통과한 원칙.
- `폐기`: 의미 변경, 과잉 적용, 기존 원칙과의 중복 때문에 더는 쓰지 않는 원칙. 폐기 이유를 남긴다.

- 근거: 사용자 사례 1개, 긍정 평가 1개, 기술 용어 반례 1개.
- 연결 평가: `HK-01A`, `HK-01B`

- 진단 질문: 이 표현은 프로젝트의 고유 명칭이나 분야 용어인가. 아니라면 같은 뜻으로 실제 한국어 문맥에서 쓰이는가.
- 적용: 섹션명, 기능명, 상태명, 짧은 표제.
- 반례: 법률명, 학술 개념, 조직에서 이미 합의한 고유 명칭은 임의로 일상어로 바꾸지 않는다.

- 진단 질문: 조사를 풀어 완전한 문장으로 만들었을 때 같은 뜻이 남는가.

- 진단 질문: 무엇을 반복할 기회인지, 어떤 조건인지, 무엇 때문에 중단했는지 문장만으로 알 수 있는가.

- 반례: 바로 앞 문장에서 대상이 명확하면 같은 말을 되풀이하지 않는다.

- 상태: `활성`
- 교정 유형: 일반 원칙 제안
- 근거: 사용자 사례 1개, 실패 1개, 수정 후 통과 1개, 방법론 반례 1개.
- 연결 평가: `HK-04A`, `HK-04B`
- 관찰: 집필·검증 방식은 홈 카드나 검색 요약이 대표해야 할 실제 내용이 아닐 수 있다.
- 진단 질문: 이 문장이 글에서 다룬 사실을 요약하는가, 제작자가 일을 처리한 방식을 보고하는가. 그 절차 자체가 독자에게 필요한 본문인가.
- 적용: 카드 설명, 검색 요약, 홈 최신 글 한 줄 소개.
- 반례: 방법론, 정정문, 검증 보고서, 투명성 보고서에서는 절차 자체가 본문 내용이다.

### 문구는 억지로 문장으로 만들지 않는다

- 상태: `활성`
- 교정 유형: 일반 원칙 제안
- 근거: 사용자 사례 1개, 표제 평가 1개, 행동 안내 반례 1개.
- 연결 평가: `HK-05A`, `HK-05B`
- 관찰: 병렬 개념을 소개하는 표제에 `한곳에 둔다`, `함께 살핀다` 같은 만능 동사를 붙이면 뜻이 흐려진다.
- 진단 질문: 동사를 지운 명사구가 더 정확하고 자연스러운가.
- 적용: 섹션 부제, 캡션, 메뉴 설명.
- 반례: 사용자가 해야 할 행동을 안내하는 버튼·도움말에는 구체적인 동사가 필요하다.

### 사실 전제는 윤문보다 먼저 확인한다

- 상태: `활성`
- 교정 유형: 의미·사실 정정에서 도출한 일반 원칙
- 근거: 사용자 사례 1개, 건강 안내 전방 테스트 1개, 기술 수치 반례 1개.
- 연결 평가: `HK-06A`, `HK-06B`
- 관찰: 문장이 유창해도 프로젝트가 중시하는 방법과 다르면 좋은 문구가 아니다.
- 진단 질문: 수치, 순서, 방법, 핵심 판단이 현재 문맥과 일치하는가.
- 적용: 훈련법, 건강정보, 제품 동작 설명.
- 반례: 의도와 사실이 이미 명시되어 있으면 불필요한 재확인을 하지 않는다.
- 주의: 특정 호흡법의 명칭과 역사적 기원은 이 원칙의 근거가 아니다. 별도 조사 없이 사실로 확장하지 않는다.

## 새 교정을 기록하는 형식

- 맥락과 문구의 역할:
- 교정 유형: `문체` / `의미·사실 정정` / `일반 원칙 제안`
- 사용자가 걸린 지점:
- 원문의 뜻과 교정 뒤 뜻의 차이:
- 일반화한 원칙:
- 다음 작업에서 던질 진단 질문:
- 적용하면 안 되는 반례:
- 근거 문맥과 증거 수:
- 연결 평가 사례:
- 외부 용례 출처와 확인 날짜: 필요한 경우에만
- 상태: `후보` / `활성` / `폐기`

한 번 나온 취향 차이는 `후보`로 둔다. 서로 다른 문맥에서 같은 문제가 반복되거나 사용자가 앞으로의 공통 원칙으로 명시하고 긍정·반례 평가를 모두 통과했을 때만 `활성`으로 올린다. 활성화하거나 폐기할 때는 상태뿐 아니라 근거와 평가 연결도 갱신한다.
