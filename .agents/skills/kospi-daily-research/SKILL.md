# KOSPI·KODEX 일일 리서치

## 실행 순서

### 1. 프로젝트 계약 읽기

- 저장소 루트의 `RESEARCH_SPEC.md`, `DATA_SOURCES.md`, `STATE.md`를 읽는다.
- 현재 `Asia/Seoul` 시각과 한국·미국 시장 상태를 확정한다.
- 빠르게 바뀌는 장중·개장 전 시황은 데이터 스냅샷 시각을 먼저 고정하고 20분 핵심판을 우선한다. 장마감·주간판은 30분을 기본 상한으로 둔다.
- 같은 날짜 보고서가 이미 있으면 덮어쓰지 말고 장중 추가판 이름을 사용한다.

### 2. 이전 상태 비교

- `STATE.md`와 가장 최근 보고서를 읽는다.
- 이전 보고서의 숫자는 비교 기준으로만 사용하고 최신값으로 재사용하지 않는다.
- 직전 전망의 성립 조건과 실제 결과를 짧게 평가한다.

### 3. 밤사이 이슈 레이더

- 고정 지표를 수집하기 전에 `references/issue-radar.md`를 읽고 개방형 이슈 탐색을 먼저 수행한다.
- 최신 주요 매체 헤드라인, 기업·규제기관 원문, 가격·거래량 이상 움직임의 원인을 서로 다른 경로로 찾는다.
- 강제청산·블록딜·마진콜, 대형 공급계약·선급금·생산능력 선점, 정책·제재·지정학·공급망 중단처럼 기존 체크리스트 밖의 사건도 후보에 넣는다.
- 후보 6~10건을 중요도 기준으로 평가하고 상위 2~4건이 보고서의 제목과 첫 분석 순서를 결정하게 한다.
- 8분 안에 후보 순위를 만들고 17분 안에 상위 사건의 핵심 사실과 전달 경로를 검증한다.
- 고정 섹션은 상위 사건을 설명하고 검증하는 근거로 사용하며, 형식을 채우기 위해 더 중요한 사건을 뒤로 밀지 않는다.
- 계약은 확정계약·MOU·협상·보도를, 청산은 일부 매각·공개주식 전량 매각·펀드 폐쇄·파산을 구분한다.
- 확인되지 않은 소셜미디어 주장은 탐색 단서로만 사용하고 공개 글에는 넣지 않는다.

### 4. 데이터 수집과 검증

- 공식·1차 자료를 먼저 확인하고 시세·시장 반응은 보조 출처로 교차 검증한다.
- 이슈 레이더 상위 사건의 전달 경로를 먼저 검증한 뒤 한국 지수·종목·투자주체, 미국 ETF·반도체, 메모리 가격, USD/KRW, 경제 일정, 미 국채를 수집한다.
- 모든 수치에 출처 표시 시각 또는 시장 상태를 기록한다.
- 정규장, 시간외, 프리마켓, 장중값을 섞지 않는다.
- ADR·EWY가 이미 끝난 한국장을 후행 반영하면 새 충격으로 중복 계산하지 않는다.
- 확인할 수 없는 항목은 추측하지 않고 `미확인`으로 표시한다.

### 5. 금리차 차트 생성

번들 Python 경로를 확인한 뒤 저장소 루트에서 실행한다.

```powershell
py -3 scripts/update_yield_spreads.py --output-dir charts
```

생성된 장기·90일 차트의 최신 날짜, 값, 오른쪽 라벨 간격을 직접 확인한다. 네트워크가 차단되면 승인을 요청하고 같은 명령을 다시 실행한다.
빠른 시황판에서는 이슈 검증과 차트 생성을 병렬로 진행하며 차트 때문에 핵심판 발행을 늦추지 않는다.

### 6. 보고서 작성

- `RESEARCH_SPEC.md`의 보고서 구조와 필수 영역을 따른다.
- 첫 부분에 기준 시각, 시장 상태, 데이터 지연 가능성을 쓴다.
- `밤사이 시장을 지배한 이슈`에서 중요도 상위 사건과 KOSPI 전달 경로를 먼저 설명한다.
- 확정 사실, 시장 해석, 조건부 전망을 구분한다.
- 메모리 펀더멘털과 주식 수급을 별도 문단으로 평가한다.
- 강세·기본·약세 시나리오마다 범위, 조건, 무효화 기준을 넣는다.
- 공격·관망·방어 합계를 100으로 맞춘다.
- KODEX 레버리지의 기초 구조 설명은 생략한다.
- 출처는 일반 Markdown 링크로 수치 가까이에 배치한다.
- `reports/YYYY-MM-DD.md`에 저장하고 차트 두 개를 삽입한다.
- 제한 시간 안에 낮은 순위 항목을 검증하지 못하면 `미확인·후속 갱신`으로 남기고 핵심판을 먼저 완성한다.

### 7. 공개 아티클과 썸네일

- 공개 아티클을 발행할 때는 `docs/CONTENT_GUIDELINES.md`와 `references/thumbnail-direction.md`를 읽는다.
- 제목·도입부·대표 이미지는 이슈 레이더 상위 1~2건에서 출발한다.
- 썸네일은 이전 썸네일을 생성 참조 이미지로 사용하지 않고 당일 사건, 방향, 정서에 맞춘 새 콘셉트로 생성한다.
- 하락장이라는 이유만으로 검정·차콜·붉은 하락 화살표를 반복하지 않는다. 독자가 사건을 이해하면서도 시각적으로 숨 쉴 수 있는 밝기와 색 대비를 우선한다.
- 공개 본문에는 라벨 배치, 차트 제작법, 내부 점수표 같은 편집 메모를 노출하지 않는다.
- 공개 본문은 확인된 사건과 그 시장 의미만 서술한다. `찾지 못했다`, `확인되지 않았다`, `추정하지 않았다`, `재사용하지 않았다`, `공지를 확인했다`처럼 조사 과정이나 제외 판단을 설명하는 문장은 보고서·`STATE.md`에만 남긴다.
- 발생하지 않은 사이드카·서킷브레이커, 발견되지 않은 계약·청산처럼 독자에게 새 정보가 되지 않는 비사건은 공개 글에서 생략한다. 확인된 발동·공시·거래가 실제 시장 원인일 때만 본문 사건으로 다룬다.
- 미확인 소문이 시장 가격을 실제로 움직여 언급이 불가피할 때는 검증 과정을 설명하지 말고, 확인된 범위와 가격 영향만 독자 문장으로 짧게 밝힌다.

### 8. 상태와 작업 문서 갱신

- `STATE.md`에 최신 실행 시각, 지수·수급, 다음 이벤트, 전망 평가, 산출물 경로를 갱신한다.
- 이슈 레이더 상위 사건과 제외한 고득점 후보의 제외 이유를 한 줄씩 남긴다.
- 스크립트나 설정을 바꿨으면 `docs/현재작업중.md`를 갱신한다.
- `scripts/check_worklog_guard.sh`와 스킬 검증기를 실행한다.

## 완료 기준

- 보고서와 두 차트가 존재한다.
- 보고서의 주요 가격·일정마다 출처가 있다.
- 차트 최신값이 스크립트 출력과 일치한다.
- 같은 사실을 ADR·EWY 시차로 중복 반영하지 않았다.
- 밤사이 후보군과 최종 상위 사건의 선택 근거가 남아 있다.
- 공개 아티클의 제목과 썸네일이 같은 핵심 사건을 전달한다.
- 장중·개장 전 핵심판은 20분, 장마감·주간판은 30분 안에 완성했거나 지연 이유와 미확인 항목을 기록했다.
- `STATE.md`가 이번 실행을 가리킨다.
- 검증과 Git 상태 확인이 끝났다.
