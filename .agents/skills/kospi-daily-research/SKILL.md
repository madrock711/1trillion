# KOSPI·KODEX 일일 리서치

## 모델 분업

- 1~5단계의 개방형 이슈 탐색, 원문 대조, 수치 검증과 시나리오 재료 정리는 `GPT-5.6 Sol Ultra`가 맡는다. 이 단계에서는 공개 원고를 쓰지 않고 출처·기준 시각·핵심 사실·전달 경로·무효화 조건만 취재 노트로 넘긴다.
- 6~7단계의 보고서 압축과 공개 원고 작성은 `GPT-5.6 Terra Medium`을 기본으로 한다. 문장 밀도나 구조가 부족할 때만 `GPT-5.6 Sol Medium`으로 집필한다. 집필 모델은 새 자료조사를 반복하지 않고 검증된 취재 노트만 사용한다.
- 최종 퇴고는 `GPT-5.6 Sol Medium`으로 짧게 수행하며 메타 문장, 중복 결론, 불필요한 유보만 제거한다. 새로운 주장이나 숫자를 추가하지 않는다.
- 모델을 나눌 수 없는 환경에서는 같은 순서를 유지하되 조사·집필·퇴고의 산출물을 섞지 않는다.

## 실행 순서

### 1. 프로젝트 계약 읽기

- 저장소 루트의 `RESEARCH_SPEC.md`, `DATA_SOURCES.md`, `STATE.md`와 `docs/KOSPI_RESEARCH_EVALUATION.md`를 읽는다.
- `research/evaluation/generated/latest.md`가 있으면 시간대별 표에서 같은 평가 구간의 거래일 중복 제거 반복 오류와 `active` 가설만 확인한다. `candidate`·`monitoring` 가설은 관찰 대상으로만 두고 오늘의 점수나 확률을 직접 바꾸지 않는다.
- 현재 `Asia/Seoul` 시각과 한국·미국 시장 상태를 확정한다.
- 빠르게 바뀌는 장중·개장 전 시황은 데이터 스냅샷 시각을 먼저 고정하고 20분 핵심판을 우선한다. 장마감·주간판은 30분을 기본 상한으로 둔다.
- 같은 날짜 보고서가 이미 있으면 덮어쓰지 말고 장중 추가판 이름을 사용한다.

### 2. 이전 상태 비교

- `STATE.md`와 가장 최근 보고서를 읽되 `STATE.md`를 현재 시세나 장 마감 실제값의 원천으로 사용하지 않는다.
- 이전 보고서의 숫자는 비교 기준으로만 사용하고 최신값으로 재사용하지 않는다.
- 새 조사 전에 `research/evaluation/forecasts`의 미정산 대표 전망과 전 거래일의 확정값을 확인한다.
- `research/evaluation/trading-sessions.json`의 KRX 거래일 순서를 갱신하고 목표일과 직전 거래일이 연속인지 확인한다.
- 장 마감 확정값이 있으면 거래일 공통 `actuals/YYYY-MM-DD.json`과 전망별 `outcomes/<forecastId>.json`을 먼저 추가한다. 확정값이 없으면 추정하지 않고 미정산으로 둔다.
- 직전 전망의 종가뿐 아니라 고가·저가 경로, 수급 유지·반전, 조건의 오탐·미탐을 같은 평가 구간끼리 비교한다.
- `scripts/evaluate_market_research.py`로 누적 요약을 갱신한 뒤 새 판단을 시작한다. 개장 전과 장중 수정판을 같은 적중률로 합치지 않는다.

### 3. 밤사이 이슈 레이더

- 고정 지표를 수집하기 전에 `references/issue-radar.md`를 읽고 개방형 이슈 탐색을 먼저 수행한다.
- 최신 주요 매체 헤드라인, 기업·규제기관 원문, 가격·거래량 이상 움직임의 원인을 서로 다른 경로로 찾는다.
- 강제청산·블록딜·마진콜, 대형 공급계약·선급금·생산능력 선점, 정책·제재·지정학·공급망 중단처럼 기존 체크리스트 밖의 사건도 후보에 넣는다.
- 후보 6~10건을 중요도 기준으로 평가하고 상위 2~4건이 보고서의 제목과 첫 분석 순서를 결정하게 한다.
- 8분 안에 후보 순위를 만들고 17분 안에 상위 사건의 핵심 사실과 전달 경로를 검증한다.
- 고정 섹션은 상위 사건을 설명하고 검증하는 근거로 사용하며, 형식을 채우기 위해 더 중요한 사건을 뒤로 밀지 않는다.
- 계약은 확정계약·MOU·협상·보도를, 청산은 일부 매각·공개주식 전량 매각·펀드 폐쇄·파산을 구분한다.
- 확인되지 않은 소셜미디어 주장은 탐색 단서로만 사용하고 공개 글에는 넣지 않는다.

### 4. 데이터 수집과 검증

- 공식·1차 자료를 먼저 확인하고 시세·시장 반응은 보조 출처로 교차 검증한다.
- 이슈 레이더 상위 사건의 전달 경로를 먼저 검증한 뒤 한국 지수·종목·투자주체, 미국 ETF·반도체, 메모리 가격, USD/KRW, 경제 일정, 미 국채를 수집한다.
- 모든 수치에 출처 표시 시각 또는 시장 상태를 기록한다.
- 정규장, 시간외, 프리마켓, 장중값을 섞지 않는다.
- ADR·EWY가 이미 끝난 한국장을 후행 반영하면 새 충격으로 중복 계산하지 않는다.
- 확인할 수 없는 항목은 추측하지 않고 `미확인`으로 표시한다.

### 5. 금리차 차트 생성

번들 Python 경로를 확인한 뒤 저장소 루트에서 실행한다.

```powershell
py -3 scripts/update_yield_spreads.py --output-dir charts
```

생성된 장기·90일 차트의 최신 날짜, 값, 오른쪽 라벨 간격을 직접 확인한다. 네트워크가 차단되면 승인을 요청하고 같은 명령을 다시 실행한다.
빠른 시황판에서는 이슈 검증과 차트 생성을 병렬로 진행하며 차트 때문에 핵심판 발행을 늦추지 않는다.

### 6. 보고서 작성

- `RESEARCH_SPEC.md`의 보고서 구조와 필수 영역을 따른다.
- 첫 부분에 기준 시각, 시장 상태, 데이터 지연 가능성을 쓴다.
- `밤사이 시장을 지배한 이슈`에서 중요도 상위 사건과 KOSPI 전달 경로를 먼저 설명한다.
- 확정 사실, 시장 해석, 조건부 전망을 구분한다.
- 메모리 펀더멘털과 주식 수급을 별도 문단으로 평가한다.
- 강세·기본·약세 시나리오마다 범위, 조건, 무효화 기준을 넣는다.
- 강세·기본·약세의 종가 범위는 겹치지 않게 만들고 각 시나리오 확률의 합을 1로 맞춘다. 장중 예상 고가·저가는 별도 `pathEnvelope`로 둔다.
- 시나리오 확률과 공격·관망·방어 점수를 분리한다. 대응 점수는 확률 대신 사용할 수 없다.
- 공격·관망·방어 합계를 100으로 맞춘다.
- KODEX 레버리지의 기초 구조 설명은 생략한다.
- 출처는 일반 Markdown 링크로 수치 가까이에 배치한다.
- `reports/YYYY-MM-DD.md`에 저장하고 차트 두 개를 삽입한다.
- 숫자 범위를 포함한 목표 거래일 종가 전망을 제시할 때 `research/evaluation/forecasts/<forecastId>.json`을 만든다. 공개·내부 구분, 당일 0 또는 바로 다음 거래일 1의 `leadSessions`, 직전 거래일, 고정 시장 국면, 발행 시각 기준 평가 구간, 기준값·데이터 기준 시각, 시나리오 확률, 대응 점수, 90% 장중 포락, 핵심 원인, AND·OR까지 재계산할 구조화된 조건, 보고서 SHA-256과 전망 계약 `contentHash`를 봉인한다. 장중 기준값은 데이터 기준 시각보다 5분 이상 낡지 않게 한다. 가설 정의의 적용 구간·국면·최소 입력 시각에 해당하면 좋은 날만 고르지 않고 모든 선택 대표에 같은 `predictorVersion`, 후보 예측과 `reference_carry` 기준을 넣는다. 회고만 있는 장마감판과 목표 거래일이 없는 주간 정리는 계약 대상에서 제외한다.
- 같은 평가 구간의 정정판은 새 `forecastId`와 `supersedes`로 한 줄의 계보를 만든다. 기존 파일을 수정하지 않으며 평가기는 마지막 leaf 판본만 누적 대표로 선택한다.
- 제한 시간 안에 낮은 순위 항목을 검증하지 못하면 `미확인·후속 갱신`으로 남기고 핵심판을 먼저 완성한다.

### 7. 공개 아티클과 썸네일

- 공개 아티클을 발행할 때는 `.agents/skills/write-finished-manuscript/SKILL.md`, `docs/CONTENT_GUIDELINES.md`와 `references/thumbnail-direction.md`를 읽는다.
- 리서치 보고서의 취재·검증 기록을 작가용 노트로 사용하되, 공개 원고는 완성 원고 쓰기의 집필 모드와 퇴고 모드를 차례로 거친다.
- 공개 원고의 제목과 본문에는 작성 계획, 조사 과정, 구조 안내, 자기평가와 후속 질문을 넣지 않는다.
- 제목·도입부·대표 이미지는 이슈 레이더 상위 1~2건에서 출발한다.
- 썸네일은 이전 썸네일을 생성 참조 이미지로 사용하지 않고 당일 사건, 방향, 정서에 맞춘 새 콘셉트로 생성한다.
- 하락장이라는 이유만으로 검정·차콜·붉은 하락 화살표를 반복하지 않는다. 독자가 사건을 이해하면서도 시각적으로 숨 쉴 수 있는 밝기와 색 대비를 우선한다.
- 공개 본문에는 라벨 배치, 차트 제작법, 내부 점수표 같은 편집 메모를 노출하지 않는다.
- 대시보드의 히어로 소개·도움말·카드 설명도 공개 본문과 같은 기준으로 쓴다. 기능 구현 목표나 데이터 연결 방식, 검증 절차, 제공하지 않는 기능의 선택 이유를 설명하지 말고 최신 스냅샷의 시장 사실과 의미를 직접 서술한다.
- 공개 본문은 확인된 사건과 그 시장 의미만 서술한다. `찾지 못했다`, `확인되지 않았다`, `추정하지 않았다`, `재사용하지 않았다`, `공지를 확인했다`처럼 조사 과정이나 제외 판단을 설명하는 문장은 보고서·`STATE.md`에만 남긴다.
- 발생하지 않은 사이드카·서킷브레이커, 발견되지 않은 계약·청산처럼 독자에게 새 정보가 되지 않는 비사건은 공개 글에서 생략한다. 확인된 발동·공시·거래가 실제 시장 원인일 때만 본문 사건으로 다룬다.
- 미확인 소문이 시장 가격을 실제로 움직여 언급이 불가피할 때는 검증 과정을 설명하지 말고, 확인된 범위와 가격 영향만 독자 문장으로 짧게 밝힌다.

### 8. 시황 대시보드 동기화

- 공개 시황을 발행할 때 `assets/data/market-dashboard-YYYYMMDD-HHMM.json`에 같은 기준 시각의 대시보드 스냅샷을 새 파일로 저장한다.
- 스냅샷의 필수 메타데이터는 `snapshotId`, `asOf`, `marketState`, 독자용 `sourceLabel`이다. 서로 다른 기준 시각을 섞어야 하면 해당 수치에 별도의 시각 라벨을 붙인다.
- 스냅샷 검증이 끝난 뒤에만 `assets/data/market-dashboard-latest.json`의 포인터를 새 파일로 갱신한다. 이 포인터는 최신판 연결 파일이므로 덮어쓸 수 있지만, 날짜·시각이 붙은 스냅샷은 덮어쓰지 않는다.
- 공개 대시보드는 페이지 로드·새로고침 때 동일 출처 읽기 전용 경로에서 KOSPI·KOSDAQ 지수, 국내 투자자·프로그램 수급, 시장 폭, KODEX 레버리지·삼성전자·SK하이닉스 당일 가격과 USD/KRW 고시환율을 다시 조회한다. 코드·거래일·시각·OHLC 검증에 실패하면 불변 스냅샷으로 안전하게 복귀한다.
- 화면에는 최신 조회값을 `시세 기준`, 발행 당시의 해석·대응 점수·시나리오·기준선을 `분석 기준`으로 분리한다. 가격 갱신만으로 전략 문장을 자동 변경하거나 현재 판단처럼 보이게 만들지 않는다.
- `articles/market.html`의 시황분석 탭에는 새 공개 글을 최신순으로 추가하고, 오늘 시황 전문 링크와 구조화 데이터도 같은 글을 가리키게 한다.
- 투자전략 탭은 공격·관망·방어 합계 100, 세 시나리오, 기준선, 이벤트, 체크리스트를 같은 스냅샷에서 렌더링한다.
- 기술적 분석 탭은 검증된 시계열이 있을 때만 이동평균·RSI·캔들을 제공한다. OHLC만 있으면 항목별 범위 비교로 표시하고 발생 순서를 알 수 없는 값을 시간 경로처럼 연결하지 않는다.
- 추천 종목 순위, 승률, 합성 컨디션 점수처럼 검증 근거가 없는 숫자를 화면 완성용으로 만들지 않는다.
- 실제 스트리밍 연결이 없는 자료에는 `실시간`이라고 쓰지 않고 날짜·기준 시각과 `장중 스냅샷` 또는 `종가`를 표시한다.

### 8-1. 발행 직전 수치 고정

- 기사 구조, 분석, 차트와 대표 이미지를 모두 끝낸 뒤 국내 장중값만 한 번의 병렬 요청으로 다시 조회한다. 지수별 직렬 조회나 수동 페이지 확인을 반복하지 않는다.
- 최종 조회 결과를 기사 표·핵심 카드·보고서·대시보드 스냅샷·`STATE.md`에 같은 작업으로 치환하고 발행 시각도 그 조회 시각으로 맞춘다.
- 최종 조회 결과를 전망 계약의 `dataCutoffAt`, `reference`, 보고서 해시에 함께 반영한다. 봉인 뒤 문장을 고치면 기존 전망 파일을 수정하지 말고 정정판을 새로 만든다.
- 최종 조회 뒤에는 새로운 조사, 이미지 생성, 문장 재구성이나 전면 QA를 하지 않는다. JSON 파싱, 핵심 합계, 링크, diff와 작업일지만 빠르게 확인한 뒤 커밋·푸시·배포한다.
- 최종 조회부터 원격 푸시까지 3분을 목표로 한다. 5분을 넘기면 전체 분석을 반복하지 말고 국내 핵심값만 다시 한 번 병렬 조회해 치환한다. 공개판이 발행 시각의 평가 구간을 넘어가면 기존 계약을 밀어 넣지 말고 새 시각·새 구간의 독립 판본을 봉인한다. `supersedes`는 같은 평가 구간 안의 정정에만 사용한다.

### 9. 상태와 작업 문서 갱신

- `STATE.md`에는 최신 실행 스냅샷과 산출물·평가 요약 경로만 남긴다. 과거 판단과 회고 본문은 누적하지 않고 평가 원장으로 이동한다.
- 이슈 레이더 상위 사건과 제외한 고득점 후보의 제외 이유를 한 줄씩 남긴다.
- `scripts/evaluate_market_research.py`를 실행해 `research/evaluation/generated/latest.json`과 `latest.md`를 갱신한다.
- 공개 판본이면 push와 배포 확인 뒤 `research/evaluation/publications/`에 `pushed`, `deploy_verified` 이벤트 JSON을 빠짐없이 각각 새로 추가한다. 둘 중 하나라도 없으면 평가기는 공개 전망을 정산하지 않는다. 내부 판본에는 publication 이벤트를 만들지 않으며 기존 이벤트나 전망 원본에 시각을 사후 덧쓰지 않는다.
- 스크립트나 설정을 바꿨으면 `docs/현재작업중.md`를 갱신한다.
- `scripts/check_worklog_guard.sh`와 스킬 검증기를 실행한다.

## 완료 기준

- 보고서와 두 차트가 존재한다.
- 보고서의 주요 가격·일정마다 출처가 있다.
- 차트 최신값이 스크립트 출력과 일치한다.
- 같은 사실을 ADR·EWY 시차로 중복 반영하지 않았다.
- 밤사이 후보군과 최종 상위 사건의 선택 근거가 남아 있다.
- 공개 아티클의 제목과 썸네일이 같은 핵심 사건을 전달한다.
- 공개 아티클이 제목과 완성 본문만으로 읽히며 과정 설명·관성적 유보·반복 결론을 남기지 않았다.
- 장중·개장 전 핵심판은 20분, 장마감·주간판은 30분 안에 완성했거나 지연 이유와 미확인 항목을 기록했다.
- `STATE.md`가 이번 실행을 가리킨다.
- 정량 종가 전망을 제시했다면 전망 계약의 보고서 해시·데이터 기준 시각·평가 구간·거래일 연속성·기준값 신선도가 검증됐고, 같은 구간의 수정 계보에 마지막 leaf가 하나뿐이다.
- 공개 전망의 `pushed`·`deploy_verified` 이벤트가 전망과 같은 `contentHash` 및 서로 동일한 commit SHA를 가리키고, 각각 `issuedAt`부터 5분·10분 안에 같은 평가 구간과 목표일 종가 전에 끝났으며, 배포 URL의 실제 가용성이 기록됐다. 같은 구간에 공개 수정판이 있어도 누적 대표는 최초 push 판본이다.
- 장중 결과에는 `postForecastPathStatus`와 경로 또는 출처 상태·시각·원문 해시를 포함한 누락 증거가 있다. 최선 적중률과 누락 실패 하한을 함께 계산하고, 누적 경로 자료 충족률 90% 미만이거나 하한이 뒷받침하지 않는 경로 성과를 인사이트로 사용하지 않았다.
- 두 수급 후보는 `promotionBlockedUntil: flow_trajectory_v1`을 유지한다. 수급 지속성 후보는 10시 이후 morning 판본, 장 후반 가속 후보는 14시 이후 판본만 적격 표본으로 센다. 평가 구간·최소 시각·predictor 판본·필수 앵커·세 지표·결과 feature는 평가기의 정본 계약과 정확히 일치해야 하며 정의 파일에서 완화하지 않는다. 전망에는 정의가 요구한 앵커·지표와 canonical input hash를 봉인하고, 장 마감 뒤 같은 actual 앵커와 대조한다. 종가 스냅샷이 없으면 종가 앵커도 누락으로 남긴다. 입력·실제·필수 결과 feature 누락은 적격 분모에 남긴다. 최근 적격 20거래일 모두 완전해 커버리지가 100%가 된 경우에만 평가기가 차단을 자동 해제한다.
- 전 거래일 확정값이 있으면 KOSPI OHLC와 원천 메타데이터, KODEX OHLCV·최종 수급·프로그램·시장 폭의 공통 실제값과 결과 판정이 추가됐으며, 하나라도 확인하지 못하면 0을 채우지 않고 누락 사유가 남아 있다.
- 표본 10개 미만의 적중률과 `candidate` 가설을 성과나 활성 인사이트로 사용하지 않았다.
- 최신 대시보드 포인터가 검증된 불변 스냅샷을 가리키고 세 탭과 시황 글 링크가 정상 작동한다.
- 검증과 Git 상태 확인이 끝났다.
